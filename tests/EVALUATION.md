# 城市初见评测集

`evaluation_cases.json` 共40条用例，期望结果独立编写，不从程序的规则计划反推答案。测试可能暴露当前能力不足，不应为了获得全通过而修改期望。

| 类别 | 数量 | 验证重点 |
| --- | ---: | --- |
| 城市认知 | 6 | 跨城市识别，饮食文化介绍不误触发餐厅搜索 |
| 需求分流 | 8 | 餐饮、书店、博物馆、影院及双领域推荐 |
| 条件筛选 | 8 | 数字与中文预算、预算分域、偏好、类别、片区 |
| 连续追问 | 10 | 两组各5轮：保留条件、修改和取消预算、移除偏好、切换城市及领域 |
| 边界输入 | 8 | 空白问题、非法预算/城市/会话、伪造已选地点、空结果、模糊需求 |

## 执行

在项目根目录运行：

```powershell
.\.venv\Scripts\python.exe test.py
.\.venv\Scripts\python.exe test.py --live
```

第一条不调用外部服务，验证现有单元测试、测试集定义和评分程序。第二条在离线通过后执行40条用例，其中6条仅做输入校验，其余34条可能多次调用高德与模型，费用高于原来的6条评测。评测无需启动网页；相同 `session` 的用例共享会话并保持文件顺序。

若前一轮失败，同一会话后续轮次标记为 BLOCKED，不继续花费额度，也不混入独立失败数。总体通过率仍以全部40条为分母，报告另列阻塞数。非连续场景使用独立会话。每轮评测使用独立数据库。

## 自动评分

- `expect.status` 默认200；输入错误必须得到指定错误码，不能用500或502代替422。
- `city`、`agents` 检查识别城市、主控分流和实际专家结果。地点须属于目标城市、真实模式及地图 ID 格式；这不构成对每个地点真实性的独立复查。
- `filters` 检查指定条件，包括显式 `null` 和空字符串；`budgets` 分别检查餐饮和娱乐预算。返回地点还需满足相应价格上限与明确指定的片区。
- `preferences_contains/excludes` 检查偏好是否保留或移除；不表示已证实某家店一定安静或不辣。
- `place_terms` 检查书店、博物馆、影院等场所的名称、类别或标签，避免只分流正确、推荐类型却错误。
- `results=required` 要求每个地点专家都有结果；`allow_empty` 允许严格筛选后无结果；`empty` 要求无结果，不允许擅自放宽片区。
- 模型或外部服务降级也记为失败，保留 notices 便于排查。

## 人工复核

报告保存回答、地点、简介/推荐理由与来源，并预留 `manual_review`。人工可按1～5分填写：

- `relevance`：地点与问题是否相关，是否适合当前意图。
- `factuality`：描述是否由来源支持，有无编造环境、特色或营业信息。
- `helpfulness`：是否帮助用户选择，有无合理解释缺失资料和空结果。

空值表示尚未人工评分，不计入自动通过率。特别是成都之外的城市介绍，目前可能缺少背景资料；路由正确并不代表介绍完整。价格、营业状态和地图数据会变化，真实评测结果不保证每次相同。

报告中不包含 token 用量或实际费用；未包含的接口故障由离线模拟测试验证。当前测试也不衡量真实热度、口味满意度、路径规划或高并发能力。
