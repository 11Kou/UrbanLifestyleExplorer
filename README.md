# 城市初见 · Urban Lifestyle Explorer

Python 城市探索助手：认识城市、发现餐饮与娱乐、对话筛选、查看地点详情和保存收藏。

## 当前实现

- **内容优先界面**：认识城市、吃什么、去哪玩、收藏夹，以及全局助手。
- **多 Agent 工作流**：主控分流 → 城市认知 / 美食 / 娱乐专家按需查询并说明理由 → 主管筛选并给出最终理由和整体建议。独立任务通过 LangGraph 并行派发。真实模式有地点候选时增加一次主管模型调用，每个有候选的领域选1～3项；纯城市介绍或无地点候选时直接保留专家结果。主管不能添加候选之外的地点或修改事实，返回无效结果时整轮回退到专家结果并提示。
- **持续探索**：保存城市、片区、预算适用范围、偏好、选中地点和最近对话；修改条件时保留其他条件。
- **独立任务与有限补查**：主管的 `tasks` 分别保存各专家的完整筛选条件，餐饮与娱乐可以使用不同预算、类别和偏好，并持久化到会话。流程为分流 → 并行专家 → 约束审核 → 按需定向补查 → 最终筛选。地点候选未通过城市、片区、预算或类别校验，或没有候选时，只重查该领域一次；补查关键词由主管建议，程序锁定任务条件并跳过原有搜索缓存。补查后再次校验，仍无结果就说明不足、请用户决定是否调整条件，绝不无限重试。城市认知当前不进入地点补查分支；软偏好仍依赖标签和人工确认。`AgentResult.attempts` 标记1次查询或2次含补查。
- **地点与依据**：事实字段来自查询结果，展示资料来源和查询时间；支持高德地图外链。
- **可解释推荐**：筛选后按偏好标签匹配、起点直线距离、地图评分、参考消费依次排序，同 ID 去重；模型可以选取候选并解释，但不改变入选地点的相对顺序。卡片及详情展示查询时的标签、片区、预算、距离和评分依据；没有对应标签支持的偏好单独标为待确认。评分不是热度，不分析评论正文，标签匹配也不代表实地核实。旧收藏缺少依据时仍可正常读取。
- **两层推荐理由**：专家理由保留在 `reason`，主管最终理由在 `supervisor_reason`；回答、卡片和详情展示最终理由。主管同时看到各专家的候选、理由、筛选依据、待确认偏好和失败提示。会话与收藏保存筛选后的地点及理由；无需数据库迁移，旧记录的新字段默认空。模型理由仍需人工检查，格式和ID校验不等于逐句事实核验。
- **地点简介与照片**：卡片用类别、所在区域、特色标签和消费信息组织简介，模型的个性化推荐理由另行展示。高德有返回地点照片时显示首图并标明来源，没有图片时保留文字卡片；暂未接入 Unsplash 或美团。
- **本地保存**：SQLite 保存会话、收藏和用户明确选择保存的偏好。
- **自动城市介绍**：成都使用已整理资料；其他城市在未配置博查时，可复用 DeepSeek 官方服务密钥调用 Search API，检索政府网站与百度百科的摘要，再生成带来源的概览、片区和饮食。正常结果缓存10分钟，失败提示缓存1分钟；首次查询会消耗搜索及模型额度，不保证每座城市都有完整资料。无需逐城手动整理，也不直接抓取百度百科网页。
- **城市切换与定位**：可手动输入国内城市；点击定位按钮授权浏览器后，以高德坐标转换和逆地理编码识别城市。无法定位时可选择本机网络 IP 粗定位，不自动获取位置、不保存原始坐标。IP 定位按运行应用电脑的出口网络估算，代理可能造成偏差；不用于精确周边搜索。浏览器定位需要本机地址或 HTTPS，以及浏览器 / 系统位置权限。

## 安装与启动（Windows / PowerShell）

本工作区已安装依赖，可直接双击项目根目录的 **启动城市初见.cmd**。双击入口使用后端 8001、页面 8502，启动后自动打开浏览器；使用期间保持启动窗口开启，按 Ctrl+C 停止服务。若通过此入口启动的应用已在运行，直接访问 http://127.0.0.1:8502 即可，接口文档位于 http://127.0.0.1:8001/docs。

需要 Python 3.11 或更高版本。在项目根目录执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe run.py
```

页面默认地址：`http://127.0.0.1:8501`。
接口文档：`http://127.0.0.1:8000/docs`。
启动器只监听本机，按 Ctrl+C 关闭它启动的两个进程。可使用 `--api-port 8001 --ui-port 8502` 修改端口。

仅检查依赖：

```powershell
.\.venv\Scripts\python.exe run.py --check
```

如果已经安装 `uv`，也可以使用 `uv venv` 和 `uv pip install -e ".[dev]"`；不要混用多个正在安装的环境。

## 演示模式

默认 `APP_MODE=demo`，无需 API 密钥。

- 收录成都的城市介绍样例和 **12 个虚构场所**。
- 名称、价格、位置、片区标签和推荐均用于交互演示，不是实际榜单或出行建议。
- Agent 分工由同一 LangGraph 流程中的规则逻辑模拟，不会调用外部模型。
- 演示场所不提供实际地图导航；周边查询展示虚构位置间的直线距离。
- 其他城市不会得到成都的演示场所。

可依次体验：

1. 在认识城市中选择玉林，进入吃什么。
2. 将人均上限设置为 50 元，收藏一个场所。
3. 查看详情，点击“问问附近还能怎么玩”。
4. 在助手中输入“换便宜一点”或“换成春熙路附近的”。
5. 打开收藏夹，查看或取消收藏；刷新相同页面可恢复会话。

## 真实接口与模型

复制 `.env.example` 为 `.env`，填入自己的服务配置并重新启动：

```dotenv
APP_MODE=live
AMAP_API_KEY=你的高德Web服务密钥
BOCHA_API_KEY=
LLM_API_KEY=你的模型服务密钥
LLM_BASE_URL=https://api.deepseek.com
LLM_MODEL=deepseek-flash
REQUEST_TIMEOUT=45
```

以上为本工作区已联调的 DeepSeek 配置。也可使用 `.env.example` 中的千问兼容接口配置；型号和权限以自己的控制台为准。博查可选；使用 DeepSeek 官方接口时，城市介绍可复用现有密钥自动搜索资料，其他兼容模型需配置博查才能联网生成介绍。DeepSeek 请求关闭思考并限制输出长度，以适配交互式 JSON 任务。

| 服务 | 用途 | 未配置时 |
| --- | --- | --- |
| 高德 Web 服务 | 地点搜索、商业信息、周边查询 | 实时地点查询明确提示缺少配置，不回退到演示数据 |
| 博查 Web Search | 城市资料、近期推荐文章与场馆信息 | 城市介绍可改用已有 DeepSeek 官方接口；餐饮娱乐的文章搜索仍需博查 |
| 大模型 | 主控任务规划、专业搜索参数选择、推荐解释 | 明确使用规则分流，不宣称正在进行模型推理 |

实际接口权限、配额、费用、型号与可用字段以各平台为准。不要把密钥写入源码或提交 `.env`。

### 数据边界

- 地图综合排序与评分不等于大众点评或其他平台的热门榜，界面标注为“地图候选 · 热度未核实”。
- 搜索文章作为背景资料单独展示，不自动声称某家分店上榜。
- 成都基础介绍来自官方历史资料，展示发布与核对日期，不代表最新商业变化。可选网页搜索失败时保留这些基础资料。
- 无消费数据的地点不参与明确预算上限的筛选。
- 餐饮预算与娱乐预算分别处理，不能把每类预算当作整晚总预算。
- 周边距离为直线距离，**当前不提供路径规划与步行耗时**；详情可跳转高德查看实际路线。
- 展馆、剧场等返回的是场所，不代表存在某一日期的活动；场次、展期和预约必须进一步确认。
- 城市资料与地点查询有短期进程内缓存，来源时间会保留。
- 当前版本用于本机个人使用；会话标识位于浏览器 URL 中，应当视为私人链接。更换浏览器或删除该标识会创建新会话。公开部署前需要身份验证与访问控制。

## 项目结构

```text
app.py                         Streamlit 页面与交互
run.py                         一键启动与依赖检查
urban_explorer/
  api.py                       FastAPI 路由与会话协调
  agents.py                    LangGraph 主控与三个专业 Agent
  planning.py                  可测试的规则计划与条件继承
  providers.py                 高德、博查、模型接口及缓存
  recommendations.py           预算、区域、偏好、距离筛选
  models.py                    Pydantic 数据契约
  storage.py                   SQLAlchemy / SQLite 本地存储
  config.py                    环境配置
  catalog.py                   演示资料与有出处的城市指南加载
  data/chengdu.json            城市与场所演示数据
  data/city-guides.json        真实模式的城市背景资料与官方出处
tests/                         核心逻辑与接口集成测试
```

同一会话的修改通过后端锁串行执行；每次专业 Agent 仅接收当前任务和必要条件，事实对象统一由数据接口创建。数据库位于 `data/city-life.db`，依赖与运行数据均不纳入版本控制。

## 验证

项目根目录的 `test.py` 是统一测试入口：

```powershell
.\.venv\Scripts\python.exe test.py
# 可选：离线通过后运行40条评测，需要 .env 密钥，会消耗接口额度。
.\.venv\Scripts\python.exe test.py --live
```

默认运行全部离线测试，并写入 `work/test-report-offline.json`，不会覆盖已有真实评测报告。`--live` 读取 `tests/evaluation_cases.json` 的40条用例，覆盖城市认知6条、需求分流8条、条件筛选8条、连续追问10条、边界输入8条。其中6条测试输入校验，不调用模型；其余34条涉及真实服务。用例与评分说明见 [tests/EVALUATION.md](tests/EVALUATION.md)。

真实报告写入 `work/test-report.json`，包括分类通过数、阻塞用例、失败原因、耗时和供人工复核的回答与地点；相同 session 的用例按顺序执行，前置失败时后续标记 BLOCKED。评测使用 `work/` 中独立数据库，无需启动页面。通过率仅代表结构与约束检查，不等于推荐质量评分，也不统计模型费用。

安装完整依赖后：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m pytest -q
```

覆盖预算与缺失价格、餐饮/娱乐预算隔离、城市切换、追问条件保留、真实起点筛选、收藏幂等和会话隔离，以及实时模式不混入演示数据。测试不调用真实外部服务。
